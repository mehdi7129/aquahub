AquaHub — guide utilisateur
Préproduction 0.2.7

1. Disponibilité et installation

Le dépôt public contient les sources et une préversion applicative 0.2.7 :
https://github.com/mehdi7129/aquahub/releases/tag/v0.2.7
Télécharger le .deb pour mettre à jour une installation AquaHub existante,
puis l’ouvrir avec le gestionnaire de paquets graphique Debian. Lire les
instructions jointes, valider l’installation, fermer et rouvrir AquaHub.
Un ZIP de sources GitHub ne s’installe pas comme une application.
Le kit complet pour un nouveau poste doit être préparé avec un bundle fournisseur
et des configurations adaptés au poste ; voir PUBLICATION.txt.

Avec un kit qualifié pour Debian 13 amd64 / GNOME, le parcours prévu est
graphique : ouvrir le .deb avec Logiciels ou l’installateur de paquets,
cliquer Installer, autoriser dans la boîte système, puis ouvrir AquaHub
dans le menu des applications. L’assistant AquaHub installe ses composants
depuis le kit local, puis propose Ouvrir AquaHub. Le client n’a pas besoin
de Node, npm, pip ou d’une commande de développement.

Le lanceur et la fenêtre portent le nom AquaHub et utilisent son icône.
Après une mise à niveau depuis 0.2.2, fermer la fenêtre déjà ouverte puis
relancer AquaHub depuis son icône habituelle pour charger la nouvelle version.
Le favori existant est conservé ; aucun redémarrage du PC n’est nécessaire.

Ne pas interrompre une étape d’installation. En cas d’échec, lire le détail
et résoudre sa cause avant de réessayer. Ne pas supprimer une configuration,
un volume ou un service existant pour contourner un diagnostic.

2. Supervision

La liste affiche les composants reconnus sur le moteur Docker natif. En cours
décrit l’état du conteneur. Validé décrit une sonde de santé définie qui
réussit ; Non défini signifie qu’aucune sonde n’existe pour ce composant.
Le contour de 2 px du badge est vert pour un service en cours, rouge pour un service
arrêté/en échec/absent, orange en transition et gris si son état actuel n’est
pas confirmé. La santé se consulte dans le détail ; un échec de sonde reste
signalé dans la liste. Le bundle reconnu a deux sondes et six composants sans sonde. Ces informations
ne valident pas les capteurs, moteurs ou conditions de navigation d’un drone.

Sélectionner un composant pour lire son détail. Actualiser relit son état.
La date de collecte et un avertissement identifient les informations périmées.
Quand la collecte est indisponible, AquaHub conserve le dernier état connu
sans prétendre qu’il est encore actuel.

Aucune tâche de maintenance signifie qu’AquaHub ne pilote aucune tâche à cet
instant. Les services du hub continuent leur activité indépendamment.

3. Relancer un service

Sélectionner le composant, choisir Redémarrer, puis vérifier le nom dans la
confirmation. Autoriser l’action dans la boîte administrateur si elle est
demandée et attendre le résultat. Une seule maintenance incompatible peut
progresser à la fois. Fermer la fenêtre n’annule pas la tâche de l’agent.
Le service ciblé passe à « Relance » en orange pendant la demande et le
redémarrage ; son détail précise la phase. À la fin, « Actualisation » en
gris attend une lecture postérieure à la tâche. « État à vérifier » indique
un résultat incertain. Une relance très rapide n’affiche pas forcément une
phase rouge : seule une observation d’arrêt ou d’échec produit cet état.

Réseau du bundle et GCS Reactor disposent d’une relance individuelle avec
contrôle des adresses et routes avant/après. Ces composants peuvent réappliquer
leurs paramètres existants au démarrage. AquaHub ne réécrit pas les paramètres
réseau pour corriger un résultat.

3.1 Vérifier ou réactiver WireGuard

Dans Supervision, sélectionner WireGuard. En cours décrit toujours le
conteneur Docker. Une seconde information décrit le tunnel local :

  Tunnel actif : le profil chargé, ses adresses et ses routes sont confirmés.
  Tunnel absent : aucune interface du tunnel n’est présente.
  Tunnel incomplet : l’interface reconnue a perdu un élément attendu ou
    n’est plus activée ; elle n’est pas présentée comme un tunnel fonctionnel.
  Tunnel non vérifié ou non pris en charge : lire le motif et renouveler
    la vérification ; aucune réactivation n’est permise depuis un état incertain.

Vérifier WireGuard renouvelle une lecture du tunnel sans demander le mot de
passe administrateur. Ce contrôle ne coupe pas le tunnel et reste possible
sans Aqua_Drone connecté, y compris sur un autre réseau.

Réactiver le tunnel est proposé pour un tunnel absent ou incomplet lorsque
le profil et l’instance sont reconnus. Lire et valider la confirmation,
puis attendre le résultat de la tâche. Depuis 0.2.7, le compte opérateur
autorisé n’a plus de mot de passe PC à saisir pour cette réactivation.
Les paramètres enregistrés ne changent
pas : seuls les éléments du tunnel déjà prévus par ce profil sont remis en
service. Aucun réglage d’adresse n’est demandé.

L’action dédiée ne redémarre pas le conteneur historique. Son démarrage
générique reste protégé ; un conteneur arrêté ou un profil non reconnu peut
nécessiter une intervention distincte. Le motif s’affiche dans le détail.
Les autres interventions administratives gardent leur protection habituelle.

Les échanges distants sont séparés de l’état du tunnel. L’absence d’échange
récent n’est pas, à elle seule, une panne. Un échange WireGuard ne prouve pas
qu’un Aqua_Drone est connecté. Un tunnel local actif ne garantit pas que le
pair ou les applications distantes sont accessibles.

Après une réponse perdue ou un résultat incertain, lire l’état et les logs
avant de demander un nouvel essai. AquaHub ne rejoue pas automatiquement la
réactivation. Les données anciennes deviennent non vérifiées ; l’application
attend une observation postérieure à la tâche avant de confirmer le nouvel
état du tunnel. Le contrat et ses limites sont détaillés dans WIREGUARD.txt.

4. Journaux et historique

Logs techniques présente les dernières lignes disponibles du composant.
Suivre active leur actualisation ; décocher permet une lecture stable.
Les journaux contiennent ce que le service écrit : ils ne décrivent pas
nécessairement toutes ses actions.

Enregistrer les logs ouvre un dialogue de destination et produit un fichier
.log avec un extrait récent, horodaté et filtré. L’export de tous les services
se trouve aussi dans Réglages → Diagnostic et assistance ; il produit un ZIP
avec un fichier par service et un résumé. Annuler ne lance pas de collecte.
L’export est limité à 1000 dernières lignes demandées et 48 Kio par service ;
un service absent, une troncature ou une lecture refusée sont signalés.
La rotation Docker du bundle limite également ce qui reste disponible.

Historique conserve les événements collectés par AquaHub. Le passé antérieur
à la collecte et les périodes sans observation ne sont pas reconstitués.
Choisir un composant ou rechercher un mot parmi les événements chargés.
Charger les événements précédents ajoute les pages anciennes.

Extrait de panne, lorsqu’il est disponible, ouvre une capture de l’incident.
Cet extrait diffère des logs courants. Troncature, expiration et absence sont
signalées. Les événements sont bornés à 365 jours et 100000 entrées ; les
extraits à 90 jours et 64 Mio au total. Ce n’est pas un archivage illimité.

5. Portainer et outils du hub

GCS, Fleet Controller et Portainer s’ouvrent dans le navigateur du poste.
Portainer est la console avancée de Docker : conteneurs, images, volumes et
journaux. Son compte administrateur protège cette console. Il n’est pas
nécessaire pour les opérations courantes d’AquaHub ni pour consulter
l’historique. Créer ce compte est utile si l’on souhaite utiliser Portainer.
Sur un Portainer neuf, choisir Réglages, Portainer, Créer le compte initial.
Le formulaire natif demande l’identifiant et un mot de passe confirmé. Un
compte déjà présent n’est pas réinitialisé.

Si Portainer propose de créer un environnement, choisir Docker Standalone
local avec le socket monté par le kit. Il n’est pas nécessaire de réimporter
une deuxième stack du bundle. Le bouton de relance conserve le compte et
les données d’une instance locale gérée reconnue.

Dans Portainer, les logs des services sont sous environnement local →
Containers → choisir le conteneur → Logs. Download logs permet l’export.
Activity logs désigne l’audit administratif documenté pour Business Edition,
pas les sorties des conteneurs. AquaHub n’a pas besoin de ce compte pour
consulter ou enregistrer les journaux des services.

6. Aqua_Drones

Les profils numérotés correspondent aux configurations du bundle ; leur
présence ne signifie pas qu’un appareil physique est connecté.

Connecter l’appareil au réseau déjà administré pour lui, puis choisir
Rechercher les appareils. Vérifier l’identité SSH lors de la première
association avec une source physique fiable. Une réponse à une IP ne prouve
pas l’identité d’un drone.

Choisir le numéro prévu, lancer Vérifier cet appareil et lire les contrôles.
Cette vérification ne demande plus le mot de passe administrateur du PC.
Elle conserve l’identité SSH et ne transfère aucune configuration au drone.
Une première association SSH reste une étape distincte.
La configuration n’est disponible que si la cible, l’identité, les fichiers
et le réseau sont compatibles. Confirmer ensuite l’identité physique avant
de lancer le travail. Depuis 0.2.4, le bouton Lancer la configuration ne
demande pas le mot de passe administrateur du PC au compte autorisé AquaHub.
La confirmation du drone reste obligatoire. Les accès SSH du drone sont
distincts ; leur association initiale et leurs réglages restent protégés.
Le drone peut redémarrer ; attendre son retour vérifié.

Le suivi nomme toujours Aqua_Drone_N. Sa barre indique les douze jalons
confirmés, avec un pourcentage fondé sur ce qui a réellement été vérifié.
Pendant une étape longue ou le redémarrage, la barre conserve son remplissage
au dernier pourcentage acquis ; une animation séparée indique l’attente. Cela n’indique pas à lui seul une panne. Le résultat
final attend le retour stable et les contrôles logiciels ; fermer la fenêtre
n’arrête pas le travail.

Configurer les appareils l’un après l’autre. Attendre la fin et vérifier le
résultat du premier avant de sélectionner le suivant. Depuis 0.2.5, choisir
un numéro inférieur ne réduit pas la flotte du hub : sur un hub déjà préparé
pour 1..5, ces appareils peuvent être choisis séparément sans ordre croissant.
La configuration active du hub reste conservée et les scripts fournisseur
restent inchangés. Un numéro absent nécessitant une extension, par exemple
6 sur ce hub, est refusé ; AquaHub ne crée pas de nouvelle configuration réseau.
La procédure peut relancer des services communs du hub : le travail parallèle
n’est pas proposé et une seconde maintenance est bloquée pendant la première.

Le numéro choisit les fichiers du bundle. AquaHub n’attribue pas d’adresse
au drone et ne configure ni routeur ni DHCP.

Le message de fin distingue le logiciel configuré des cinq contrôles manuels.
Le petit bouton « i » en donne le détail au survol et au focus clavier ;
un clic ouvre la liste complète :

  1. RUTC50 : vérifier la configuration LAN déjà installée, sans modifier
     les adresses IP.
  2. RUTC50 : vérifier la route et le prochain saut existants vers le GCS,
     sans modifier les IP ni les routes.
  3. Pilote automatique : contrôler MAV_SYS_ID = numéro de l’appareil,
     l’écartement des antennes EKF2_GPS_POS_Y, EKF2_GPS_POS_X/Z = 0,
     BT_POS_XY_P/I/D, BT_POS_IMAX et la numérotation des moteurs selon
     les spécifications du matériel et du fournisseur.
  4. Heron : relever les versions Firmware et BL (bootloader).
  5. Console MAVLink / nsh : contrôler uavcan status, gps status et
     listener esc_status pour le CAN, le GPS et les moteurs.

Les deux premiers éléments sont des rappels consultatifs. AquaHub n’exécute
aucune modification réseau pour les réaliser. Les cinq éléments ne sont pas
validés automatiquement par la réussite de la configuration logicielle.

Le profil SSH sans secret ne doit être activé que pour un firmware qui le
prévoit. Il ne dispense jamais de vérifier l’empreinte SSH ni un changement
d’identité. Les clés privées ne sont pas saisies dans le renderer.

7. Mettre l’application AquaHub à jour

Dans Mises à jour, le premier bloc Application AquaHub affiche la version
et le bouton de recherche. La source officielle est intégrée à l’application,
sans URL à configurer. Une connexion Internet est nécessaire pour rechercher
et télécharger une nouvelle version.

Choisir Rechercher une mise à jour. Si une version
stable compatible est proposée, lire ses notes puis choisir Télécharger.
Le paquet est vérifié avant que le bouton Installer ne soit disponible.
Confirmer ensuite l’installation et autoriser la demande système.

AquaHub et son agent seront remplacés ; les services du bundle, ses données
et les configurations réseau restent indépendants de cette opération.
L’agent peut se déconnecter pendant sa mise à jour. Attendre le résultat
contrôlé sans relancer une deuxième installation, puis fermer et rouvrir
AquaHub pour charger la nouvelle interface. En échec, lire le message et
le diagnostic ; il n’existe pas encore de retour automatique à l’ancienne
version de l’application.

La préversion publique 0.2.7 se télécharge manuellement depuis sa page Release.
Le canal automatique ignore volontairement les préversions. Le paquet est
une mise à niveau pour un poste déjà initialisé, pas un kit de première
installation. Le kit complet hors ligne reste un autre artefact.

8. Mettre le bundle fournisseur à jour

La recherche en ligne est présentée en premier. Le connecteur actuel permet
de consulter des livraisons publiées ; le parcours Git + registre spécifique
du fournisseur attend encore sa qualification.

La section située en bas permet d’installer depuis une archive déjà
téléchargée. Choisir une archive de bundle lance son inspection. Une archive reconnue peut
rester non applicable ; l’intégrité seule ne prouve pas sa compatibilité.
Une application autorisée possède une confirmation distincte et peut
interrompre les services. Lire le résultat et la disponibilité du retour
arrière ; un échec restauré reste un échec de mise à jour.

Le réglage Source du bundle Aqua Hub concerne les livraisons du fournisseur.
Ne pas y substituer le dépôt AquaHub pour mettre l’application à jour.
La recherche de ce bloc consulte une API de Releases, et non le dépôt Git
ou le registre Docker. Un jeton de déploiement autorisant Git et le registre
Docker ne suffit pas à l’API des Releases GitLab. Un message projet absent
ou privé peut signifier qu’aucun accès API adapté n’a été enregistré.

Le fournisseur peut distribuer du code et des images Docker sans publier
de Release. Son flux Git + registre attend une procédure de mise à jour
qualifiée ; il ne faut pas lancer install.sh ni modifier les IP pour
contourner cette limite. L’import d’une archive fournisseur reste disponible,
avec les mêmes contrôles de compatibilité avant application.

9. Diagnostic et signalement

Réglages permet de créer un diagnostic local filtré. Son export n’est pas
un envoi automatique à un service distant. Vérifier son contenu avant de
le communiquer ; un secret dans un format inconnu peut échapper au filtre.
Pour une issue publique, donner la version, le symptôme et une reproduction
sans identité de matériel, configuration client ni journal brut privé.
