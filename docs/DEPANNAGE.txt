AquaHub — dépannage du développement

Le diagnostic commence par le mode utilisé : démo, fixture synthétique ou
agent réel. Ne pas corriger un problème de banc en relâchant une garde du
produit. Les commandes de cette page sont destinées au développeur.

Module gi introuvable

Utiliser /usr/bin/python3 et vérifier les paquets python3-gi, GTK et WebKitGTK.
Un venv isolé peut masquer ces bindings système. L’agent et les tests sans
affichage n’ont pas besoin que la fenêtre GTK soit ouverte.

Ressources de l’application absentes

Compiler depuis frontend/ avec npm ci puis npm run build. Vérifier les trois
fichiers de frontend/dist/. --frontend permet de sélectionner une construction
précise. Un lancement depuis les sources ne lit pas automatiquement un serveur
de développement ; l’interface livrée est locale.

La fenêtre utilise un agent inattendu

Vérifier --socket, --no-agent, les chemins d’état et la présence d’une
installation système. Le produit installé ne crée pas un agent de session
de secours. Pour l’interface seule, utiliser la commande --demo du guide de
reprise, avec un socket inutilisé et un état local-private/ distinct.

Une lecture de paramètres attend une autorisation

Les réglages SSH et certaines préparations sont des méthodes protégées,
même en lecture. Une fixture sans agent PolicyKit interactif ne prouve pas
leur fonctionnement autorisé. Les tests natifs synthétiques utilisent leur
propre serveur ; un banc réel doit suivre son parcours d’autorisation.
Ne pas ajouter de règle PolicyKit permanente pour faire passer la recette.

Depuis 0.2.1, le bouton Vérifier cet appareil ne demande plus PolicyKit.
Si une fenêtre administrateur apparaît pour ce bouton, vérifier que le
desktop ET l’agent installé utilisent cette version. La première association
SSH reste distincte ; une identité inconnue ne doit pas être approuvée pour
faire disparaître une erreur. Une maintenance en cours peut refuser le
précontrôle sans demander de mot de passe.

Les badges sont gris alors que le dernier état disait En cours

Le gris signifie que l’état actuel n’est plus confirmé : collecte périmée,
agent déconnecté ou réponse retardée. Le délai de fraîcheur est de 30 secondes.
Relire la connexion ou les journaux de l’agent ; ne pas remplacer ce gris
par un vert à partir des dernières données mises en cache.

Activity logs est vide dans Portainer

Cette page vise l’audit administratif documenté pour Business Edition.
Les logs des services sont sous environnement local → Containers → le
conteneur → Logs. Dans AquaHub : Supervision → service → Logs techniques.
Enregistrer les logs et l’export groupé produisent des extraits filtrés,
pas un historique exhaustif. La rotation du bundle est de 10m × 3 fichiers
par conteneur ; une plage ancienne peut donc ne plus être disponible.

Bundle inconnu ou archive non applicable

Lire l’échec du précontrôle. Comparer les versions et le contrat reconnu,
pas seulement le nom du fichier. Une archive intègre peut contenir un schéma,
un Compose ou des images incompatibles. Ne pas changer un hash attendu sans
qualifier le nouveau comportement ; voir CONTRAT_BUNDLE.txt.

Conteneurs présents mais absents d’une lecture Compose

Comparer le moteur, le projet Compose, le dossier et le fichier utilisés.
Le nom du dossier peut différer du projet explicite aqua-hub-bundle. Le moteur
de mise à jour centralise les appels dans _compose() ; garder le projet
explicite dans tout nouvel appel. Le contexte de l’utilisateur ou sa variable
COMPOSE_PROJECT_NAME n’est pas une source d’autorité pour l’agent.

Six services sans sonde

C’est le contrat actuel du bundle, pas une erreur de rendu. Running ne veut
pas dire healthy et l’absence de sonde ne signifie pas panne. Développer une
nouvelle sonde avec le fournisseur et vérifier le comportement métier réel.

Projet ou livraison GitLab absent, privé ou inaccessible

La source du bundle consulte l’API des Releases GitLab. Vérifier l’URL du
projet et l’accès API configuré dans AquaHub. Un jeton de déploiement Git /
registre Docker n’autorise pas cette API ; un clone réussi ne prouve pas
l’accès aux Releases. GitLab peut renvoyer 404 pour masquer un projet privé.
Ne pas en conclure automatiquement que le jeton Git fourni est invalide.

Il est aussi possible qu’aucune Release ne soit publiée, même si le dépôt
et les images existent. Le flux fournisseur Git + registre reste distinct
et attend sa procédure qualifiée. Ne pas remplacer la source du bundle par
le dépôt AquaHub et ne pas lancer le script fournisseur pour contourner
une archive non applicable.

Aucune mise à jour AquaHub proposée après un commit Git

Le bloc Application AquaHub recherche des Releases stables publiques du dépôt
fixe mehdi7129/aquahub, pas la dernière branche ou le dernier commit. Il faut
un tag X.Y.Z ou vX.Y.Z et l’asset exact aquahub-application_X.Y.Z_amd64.deb,
avec taille et digest SHA-256 GitHub disponibles. Brouillons, préversions,
ZIP de sources, kits complets et fichiers sans intégrité vérifiable sont
ignorés. Vérifier aussi la connexion Internet et une éventuelle limite API.
Aucune Release publique n’est encore annoncée avec les sources 0.2.1.

L’agent disparaît pendant la mise à jour de l’application

Le helper indépendant remplace AquaHub et redémarre son agent. La fenêtre
suit app_updates.status ; une coupure transitoire est attendue. Ne pas
réenvoyer install à chaque échec de connexion. scheduled ou installing ne
prouve pas un succès ; attendre installed ou failed. Fermer puis rouvrir
la fenêtre après installed pour recharger la nouvelle interface.

Sur un banc autorisé, le résultat et le journal privé sont sous
/var/lib/aquahub/agent/app-updates/ ; le service transitoire est
  aquahub-application-upgrade.service.
Ne pas publier ces fichiers bruts. Si le paquet échoue, le helper tente
de relancer l’agent et écrit failed ; il n’effectue pas de restauration
automatique de l’ancien paquet. Le rollback d’images du bundle ne s’applique
pas à l’application.

La progression d’un drone reste au même pourcentage

Le pourcentage compte les jalons validés, pas le temps écoulé. Pendant une
copie, une commande fournisseur ou l’attente du redémarrage, la barre peut
rester indéterminée. Lire le nom de l’appareil et l’étape. Un résultat
logiciel réussi ne valide pas les cinq contrôles manuels. Le bouton « i »
donne la liste. Deux éléments sont consultatifs : vérifications du LAN et
de la route existants, sans modification des IP par AquaHub.

Retour arrière refusé

Lire si la sauvegarde est corrompue, la configuration ou le réseau ont changé,
ou le retour n’a pas été confirmé. Préserver les preuves et éviter une seconde
intervention concurrente. Le moteur ne remet pas automatiquement d’anciennes
IP et ne couvre pas les migrations de données du fournisseur.

Test de socket Unix : chemin trop long

Les sockets AF_UNIX ont une longueur limitée. Les bancs natifs du dépôt
créent leurs sockets synthétiques dans un répertoire temporaire court.
Conserver cette propriété lorsqu’on ajoute une fixture ; ne pas utiliser
un chemin de checkout long comme emplacement d’une socket de test.

Retrait de paquet refusé pendant maintenance

Le verrou est volontaire. Attendre le résultat réel de la tâche avant de
réessayer. dpkg peut modifier sa sélection souhaitée même si prerm refuse
le retrait ; distinguer cette métadonnée de l’état effectivement installé.
Sur un banc, vérifier le paquet et les services plutôt que supposer le retrait.

Incident à signaler

Donner la version, la commande ou le parcours utilisé, la cible simulée ou
réelle, le code d’erreur et une reproduction expurgée. Ne pas déposer la base
SQLite, une archive client, un fichier SSH ou les logs bruts d’un fournisseur
dans une issue publique.
